## 0. Architecture overview

**What it is.** A feature-first **Nx monorepo** (pnpm workspaces, Node ≥20) hosting:
- a **Next.js 15 App Router** frontend (`apps/frontend`) with a real-time, scroll-scrubbed **three.js**
  cinematic villa walkthrough on the homepage, plus an admin panel; and
- a fleet of **isolated NestJS microservices** behind a single **API gateway** — the only public door.

**Services (11 deployable apps):** `gateway`, `auth-service`, `cms-service`, `project-service`,
`service-management`, `contact-service`, `quotation-service`, `media-service`, `notification-service`,
`admin-service` (BFF aggregator), and `frontend`.

**Guiding principles (from `docs/ARCHITECTURE.md`):** isolation over convenience (database-per-service, no
cross-service DB reads); Clean Architecture / DDD inside each service (domain → application → infrastructure
→ presentation, dependencies point inward); contracts-as-code in `@fardeen/types`; the gateway is the only
public entry; performance is a feature.

**Two communication planes:**
- **Synchronous** — browser → **gateway** (REST/JSON) → services (NestJS transport, typed message patterns).
- **Asynchronous** — services publish domain events (e.g. `contact.submitted`, `quotation.statusChanged`) to
  **Redis pub/sub**; `notification-service` subscribes and sends email out-of-band.

**Data ownership (database-per-service on one PostgreSQL):** `auth_db`, `cms_db`, `project_db`, `service_db`,
`contact_db`, `quotation_db`, `media_db`, `notification_db`. `admin-service` owns no DB (pure aggregator).
Binary assets live in **MinIO** (S3 API) via `media-service` presigned URLs. **Redis** also serves as a cache.

**Security:** JWT access tokens (short TTL) verified at the gateway; opaque rotating refresh tokens in an
`httpOnly`/`Secure`/`SameSite` cookie; RBAC roles; Helmet + CORS allowlist + rate limits; env validated at boot.

> **Doc vs. code note:** `docs/ARCHITECTURE.md` is the original design spec and is partly aspirational — it
> describes react-three-fiber, TanStack Query, and a `features/`-style frontend tree. The **actual**
> implementation uses **raw three.js** (no R3F) for the cinematic, RSC data-fetching with `safe()` fallbacks,
> and the folder layout documented in §11–§12 below. Where this reference and that doc disagree, **this
> reference reflects the shipped code.**

## 1. auth-service & API gateway

### auth-service

- **Purpose & role**: The identity & access microservice — the sole owner of `auth_db` (users + refresh sessions). It handles registration, login, JWT access-token minting (RS256), refresh-token rotation with reuse detection, logout, and profile reads. It exposes **no public HTTP business API**; the gateway is its only caller, over a TCP microservice transport via `@MessagePattern`. A tiny HTTP server runs alongside only for `/health` + `/ready` probes.
- **Tech/framework**: NestJS 10, hybrid HTTP + `Transport.TCP`. Prisma 6 (PostgreSQL, client → `apps/auth-service/generated/client`), `ioredis` (refresh-session store + event bus), `jsonwebtoken` (RS256), `bcryptjs` (hashing), `zod` (config). Clean/Hexagonal architecture; use-cases wired via `useFactory`. Depends on `@fardeen/shared`, `@fardeen/types`, `@fardeen/utils`.

**HTTP endpoints**: only `/health` + `/ready`. **TCP `@MessagePattern` handlers** (the real API), each returns `Result<T>`:
| Pattern | Handler | Payload | Success data | Error codes |
|---|---|---|---|---|
| `auth.register` | RegisterUser | `RegisterPayload {email,password,role?,correlationId?}` | `UserProfile` | `EMAIL_TAKEN`, `VALIDATION_ERROR` |
| `auth.login` | LoginUser | `LoginPayload {email,password,userAgent?,correlationId?}` | `LoginResult {access,refreshToken,profile}` | `INVALID_CREDENTIALS` |
| `auth.refresh` | RefreshToken | `RefreshPayload {refreshToken,userAgent?,correlationId?}` | `RefreshResult {access,refreshToken}` | `REFRESH_INVALID`, `REFRESH_REUSE`, `UNAUTHORIZED` |
| `auth.logout` | Logout | `LogoutPayload {refreshToken}` | `{ ok:true }` | – (idempotent) |

**Guards/interceptors/filters**: none (pure TCP microservice + thin health controller; all HTTP cross-cutting concerns live at the gateway).

**Auth mechanics (exact)**:
- **Access token** — RS256 JWT (`Rs256TokenSigner`). Claims `sub`=id, `email`, `role`, `type:'access'`, `iss`=`JWT_ISSUER` (default `fardeen-auth`), `aud`=`JWT_AUDIENCE` (default `fardeen-api`), `exp` from `JWT_ACCESS_TTL` (**default 900s = 15 min**). Returned as `{accessToken, tokenType:'Bearer', expiresIn}`.
- **Refresh token** — opaque random 32-byte hex; **only its SHA-256 hash stored** in Redis; raw returned to gateway for the cookie. TTL `REFRESH_TTL_SECONDS` (**default 1209600s = 14 days**), keys stored with +60s slack.
- **Redis layout** — token at `auth:rt:tok:<sha256(token)>` (JSON `{userId,familyId,active,expiresAt,userAgent}`); family set at `auth:rt:fam:<familyId>`.
- **Rotation** — every `auth.refresh` marks the presented token `active=false` and issues a new token in the **same family** + new access token.
- **Reuse detection** — presenting an existing-but-inactive token → `revokeFamily(familyId)` deletes the whole family → `REFRESH_REUSE`. Expired → `REFRESH_INVALID`; inactive user on refresh → family revoked + `UNAUTHORIZED`.
- **Logout** — revokes the entire family; idempotent.
- **Password hashing** — bcrypt rounds `BCRYPT_ROUNDS` (**default 10**). Login `verifyPassword` first checks `isActive()`.
- **Cookies** — none here (auth-service returns only the opaque `refreshToken`; the gateway owns the cookie).

**Config / env vars**: `SERVICE_NAME` (auth-service); `TCP_PORT` (config default 4010; main.ts fallback 4001); `HTTP_PORT` (3010/3001); `AUTH_DATABASE_URL` (required); `REDIS_HOST`/`REDIS_PORT`/`REDIS_PASSWORD`; `JWT_PRIVATE_KEY` or `JWT_PRIVATE_KEY_PATH` (one required); `JWT_ACCESS_TTL` (900); `JWT_ISSUER` (fardeen-auth); `JWT_AUDIENCE` (fardeen-api); `REFRESH_TTL_SECONDS` (1209600); `BCRYPT_ROUNDS` (10); `SERVICE_BIND_HOST` (0.0.0.0); `READY_CHECK_*` + probe targets. Seed: `AUTH_DATABASE_URL`??`DATABASE_URL`, optional `SEED_ADMIN_EMAIL`/`SEED_ADMIN_PASSWORD`.

**Prisma schema**:
- **User** (`users`): `id @default(uuid())`; `email @unique`; `passwordHash @map("password_hash")`; `role String @default("visitor")`; `status String @default("active")`; `createdAt`; `updatedAt`.
- **RefreshSession** (`refresh_sessions`, audit-of-record; live store is Redis): `id`; `userId @map("user_id")`; `tokenHash @unique @map("token_hash")`; `familyId @map("family_id")`; `userAgent String?`; `expiresAt`; `revokedAt DateTime?`; `createdAt`; indexes `@@index([userId])`, `@@index([familyId])`. No enums; role/status plain strings.

**Events**: publishes `user.registered` (`{userId, email, role}`) via dual-write XADD `stream:user.registered` + PUBLISH. `user.roleChanged` declared but not emitted. Consumes none.

**Tests**: unit use-case specs (get-me/login/logout/refresh/register), entity+VO specs, di-tokens spec; integration `auth-flow.integration.spec.ts` vs real Postgres `auth_db_test` + real Redis (RS256 sign→verify + RBAC claim, rotation, reuse detection revoking family keys, single INVALID_CREDENTIALS; uses `secrets/jwt-*.pem`).

**Ports**: TCP `TCP_PORT` (default 4010; gateway dials this) + HTTP `HTTP_PORT` (default 3010), bind 0.0.0.0.

### gateway

- **Purpose & role**: The single public-facing API gateway — the only public door. Terminates HTTP/REST under prefix `/api/v1`, verifies RS256 access tokens **locally** with the public key (no round-trip to auth-service), enforces RBAC + rate limiting + CORS + Helmet, attaches correlation ids, and **proxies/aggregates** each request to the owning microservice over per-context TCP `ClientProxy`, composing media references gateway-side. **Stateless — no database, no Prisma.**
- **Tech/framework**: NestJS 10, `@nestjs/jwt` (present) + `jsonwebtoken` (actual RS256 verify), `@nestjs/throttler` (rate limit), `helmet`, `cookie-parser`, `class-validator`/`class-transformer` (global `ValidationPipe`), `zod` (via `ZodBody`), rxjs `firstValueFrom`. Depends on `@fardeen/shared`/`@fardeen/types`/`@fardeen/utils`.

**File tree — `src/`**: `main.ts` (helmet, cookieParser, CORS credentials, global prefix `api/v1`, global ValidationPipe, listen `GATEWAY_PORT`); `app.module.ts` (ThrottlerModule.forRoot, 9 controllers, one ClientProxy per context, global ThrottlerGuard/AllExceptionsFilter/ResponseEnvelopeInterceptor, CorrelationIdMiddleware on `*`); `config/env.ts` (`GATEWAY_CONFIG` + Zod, loads JWT **public** key, service host/port map, cookie/rate-limit); `health/health.controller.ts`; `auth/{jwt.guard,roles.decorator,roles.guard}.ts`; `common/*` (all-exceptions.filter, client.util `callService`, clients-warmup, correlation.middleware, domain-http.error, http-status.map, http.ts `FardeenRequest`, media-resolver, response.interceptor, zod-body.pipe); `presentation/*.controller.ts` (auth, admin, contact, content, media, projects, quotations, services).

**Prisma**: none (stateless). **DTOs**: no local class-validator DTOs; validates via `ZodBody` against shared schemas + a few local admin Zod schemas (`listQuerySchema`, `contactStatusSchema`, `quotationStatusSchema`). **Events**: none directly (forwards `correlationId` in TCP payloads). **Tests**: none. **Ports**: HTTP `GATEWAY_PORT` (default 4000) serving `/api/v1`; dials downstream TCP ports.

## 7. Cinematic 3D villa walkthrough

The homepage hero is a **scroll-scrubbed, real-time three.js film**: an empty plot builds itself into a
luxury villa while a single camera flies through it (dawn → golden hour → evening). It is written in
**raw three.js** — React is deliberately kept out of the render/scroll path (no react-three-fiber). The
whole journey is **one continuous procedural world** driven by **one GSAP timeline** scrubbed by scroll.

### File map
| File | Role |
|---|---|
| `src/lib/cinematic/world.ts` (~4.8k lines) | Builds the entire procedural world in three.js: sky, terrain, grass, birds, landscape, gate, and the villa (slab→rebar→columns→walls→upper→roof→cladding→glass→interior). Returns a `World` (scene, camera, mutable `handles`, `updateAmbient`, `dispose`). Also `enrichWorld()` — the async realism pass. |
| `src/lib/cinematic/scenes.ts` | Pure scene-direction data: the 13 `SceneDef`s (camera keyframes + per-scene walking `route`s), `OPENING_CAMERA`, `PALETTE` (golden-hour colour stops), `BRAND` colours, `sceneWindow()`. No React state. |
| `src/lib/cinematic/director.ts` | `createDirector()` — builds the ONE scrubbed GSAP timeline + ScrollTrigger. Every tween writes directly to three.js objects (camera, materials, transforms, door pivots). Owns visibility via `applyVisibilityAt(time)`. Returns `{ seek, progress, time, dispose }`. |
| `src/lib/cinematic/assets.ts` | Async loaders: `loadEnvironment` (HDRI IBL), `loadModel` (GLB), `loadPbr` (CC0 PBR texture sets), `createModelLoader`. Each is failure-guarded. |
| `src/lib/cinematic/pipeline.ts` | Renderer/post-processing pipeline helpers (tone mapping, exposure, quality tiers). |
| `src/components/cinematic/cinematic-experience.tsx` | Client component that mounts the WebGL canvas, creates the renderer + demand render loop, wires Lenis smooth-scroll, instantiates the world + director, runs `enrichWorld`, and exposes the verification seams `window.__fardeenSeek/__fardeenPerf/__fardeenBenchmark`. |
| `src/components/cinematic/cinematic-mount.tsx` | Gate + fallback. Renders the heavy 3D only when WebGL is available, motion is allowed, and the viewport is ≥1024px; otherwise renders a static `StaticInteriorNavigator` (room cards). Holds `STATIC_ROOMS`. |
| `src/components/cinematic/walkthrough-scrubber.tsx` | The scroll spacer / progress affordance for the pinned canvas. |
| `src/lib/cinematic/scenes.spec.ts` | Unit tests over the scene data (monotonic windows, valid keyframes). |

### The world (`world.ts`)
- **`WorldHandles`** is the mutable contract the director tweens: `env` (skyMat, fog, sun, ambient), `site`,
  and `villa` (slab, rebar, walls[], columns[], upper, roof, shellMats, claddingMat, glassMat, windowMat,
  interior, interiorLight, windowMesh, floorMat, marbleMat, furnitureGroup, finishes, exteriorShell,
  upperLeftFacade, `mainDoor`, `groundBedroomDoor`, `groundBathDoor`, and `rooms`).
- **`rooms`**: `living, dining, kitchen, stairs, landing, master, masterBath, commonBath, secondBedroom,
  terrace` — each a `THREE.Group` toggled by the director. (`stairs` is actually the **exterior** staircase;
  `living` also contains the ground-floor guest suite.)
- **Villa footprint**: interior `x∈[-6,6]`, `z∈[-4.35,4.35]`. Back wall `z=-4.35`, west `x=-6`, east `x=+6`,
  front `z=+4.35` with a glazed portal opening `x∈[-2.2,2.2]` and a hinged wood `mainDoor`.
- **Ground-floor plan**: living hall (west-front), kitchen + dining (east), and a **premium guest bedroom
  suite with an attached ensuite** carved into the west-back quadrant. First floor (via the **exterior**
  east staircase): master bedroom, its attached washroom, second bedroom, terrace.
- **Primitives & helpers**: `box(parent,[w,h,d],[x,y,z],mat)`, `cylinder(...)`, `growGroup`, `roomShell`
  (builds a room's floor + walls with optional door cut-outs), `ceilingLight`, `pendant`, `tableLamp`,
  `chair`, `plate`, `acUnit`.
- **Static batching (`batchRoom`)**: after each room is populated, its meshes are **merged by material**
  into one mesh per material (bakes world transforms, drops draw calls) so weak GPUs stay fast while every
  completed room remains visible ("persistence"). Merged inputs are normalised to non-indexed before
  `mergeGeometries`. **Animated door pivots are detached before the merge and re-attached after**, so they
  remain live, animatable objects (the `mainDoor`, `groundBedroomDoor`, and `groundBathDoor`).
- **`enrichWorld(world, renderer, invalidate)`**: post-mount async realism pass — loads the HDRI for
  image-based lighting/reflections and grafts real CC0 PBR maps onto the procedural materials. Every asset
  is guarded (failure → keep the solid colour), and `invalidate()` repaints after each graft.

### The scenes (`scenes.ts`)
13 scenes, each owning a 1-unit window on the timeline (`sceneWindow(id) = [id-1, id]`; total length = 13):
1 empty-land · 2 foundation · 3 structure · 4 villa-transformation · 5 approach-gate · 6 hall (living) ·
7 kitchen-dining · 8 guest suite (ground bedroom + ensuite) · 9 exit → exterior stairs → master bedroom ·
10 attached washroom · 11 second bedroom · 12 terrace · 13 reveal ("We build the moment you walk in").
Each `SceneDef` has `camera` (end keyframe), optional `route` (piecewise walking waypoints with `at∈[0,1]`),
`ease`, and overlay `eyebrow`/`title`. `PALETTE` holds keyed sky/fog/light colour stops (dawn→warm→golden→
evening) anchored to scene indices `[0,2,4,7,10]`. `BRAND` = gold/ink brand colours for the 3D materials.

### The director (`director.ts`)
- Sets the **canonical progress-zero state** (everything hidden/flat) so async enrichment can never flash a
  finished building before ScrollTrigger owns the scene. Doors (`mainDoor`, `groundBedroomDoor`,
  `groundBathDoor`) start CLOSED (`rotation.y = 0`).
- Builds **one** `gsap.timeline` bound to a `ScrollTrigger` on the spacer (`scrub: 0.5`,
  `invalidateOnRefresh`). The camera path is authored per scene: routed scenes tween through their waypoints;
  unrouted scenes ease to the end keyframe then hold for the caption.
- **Construction tweens**: slab pour, rebar, columns/walls rising, upper setback, roof drop, cladding/glass/
  emissive-window reveals, gate open, and the **main door swing** (open at t≈5.02, close at t≈12.04).
- **Door choreography (Scene 8 window [7,8])**: the guest-bedroom door swings open as the camera reaches the
  doorway and shuts as it leaves; the ensuite door opens for the washroom leg and closes on exit — all as
  absolute-position tweens so forward/reverse scrubbing is deterministic.
- **Visibility** is a **pure function of current time** (`applyVisibilityAt`) — no historical latch: down-scroll
  reveals additively, reverse-scroll removes in the exact opposite order, `t=0` returns to terrain/grass/fog
  only. `roomReveals` map rooms to reveal thresholds; the middle window uses an **open-top cutaway** (roof/upper
  massing removed during the interior tour) while the final exterior (`t≥12`) restores the massing and hides
  the cutaway interior. Walls are never hidden — occlusion is physical (closed doors + walls).
- Returns `{ seek(p), progress(), time(), dispose() }`; `seek` clamps `p∈[0,1]`, sets timeline progress, and
  re-applies visibility. `dispose` reverts the gsap context.

### Mount, gating & seams
- `cinematic-mount.tsx` renders the 3D only when WebGL + motion are OK **and** viewport ≥1024px; phones get the
  static `StaticInteriorNavigator` (room cards) for performance. Reduced-motion → static fallback too.
- `cinematic-experience.tsx` exposes verification seams on `window`: **`__fardeenSeek(p)`** (drive timeline
  progress 0–1), **`__fardeenPerf`** (last perf reading), **`__fardeenBenchmark(ms)`** (measure steady-state
  FPS/draw-calls/tier). Used by `scripts/probe-cinematic-gpu.cjs` (Playwright) for headless FPS + screenshot
  verification. The canvas lives in a `[data-cinematic-spacer]` scroll container.
- Performance: adaptive quality tiers (weak-GPU detection lowers pixel ratio / shadow quality); demand render
  loop (renders one frame per scrub tick via `invalidate()`), not a free-running RAF.

### How to run (documented workflow)
**Full Docker (parity/CI):** `cp .env.example .env` → edit secrets → `docker compose up` (FE, gateway, 9 services, postgres[8 DBs], redis, minio). FE http://localhost:3000 · Gateway http://localhost:4000/api/v1/health · MinIO console http://localhost:9001. Health-gated boot; hot reload via bind-mount + Nx watch + polling.
**Light dev (Windows, no Docker — the actual mode here):** native infra (Postgres 5432 + Redis 6379 from `fardeen-dev-infra`), services as compiled `dist` (`node dist/main.js`, ~70MB each): `.\dev-up.ps1` (ensure infra, build stale dist, start 10 services + FE, hold terminal); `-Prod` (FE as production build ~200MB); `-Rebuild`; `.\dev-down.ps1`. Alt: `pnpm dev:infra` + `pnpm nx dev <app>`. Site http://localhost:3000 · Admin /admin · API http://localhost:4000/api/v1.
**Build order:** `^build` in Nx builds packages before apps; dev-up builds `types,shared,utils` then 10 services (`--parallel=1`), starting owning/leaf → BFF → gateway; compiled runs env-bootstrapped by `scripts/run-svc.cjs`.
**Production:** `docker compose -f docker-compose.prod.yml build` → `… up -d` → `… --profile migrate run --rm migrate` (one-shot Prisma migrations).
**Integration tests:** `pnpm test:integration:setup` then `pnpm test:integration`. **E2E:** `.\dev-up.ps1` then `npx playwright test`.
