## 0. Architecture overview

### 0.1 What Fardeen is
A production-grade marketing + content platform for a full-solution construction company (construction,
interior design, modular kitchen, aluminium/glass work, ACP cladding, steel fabrication). A public
Next.js site (marketing + a scroll-driven cinematic hero) plus a protected admin panel, backed by a
fleet of isolated NestJS microservices behind a single API gateway.

### 0.2 Tech stack
| Layer | Technology |
|---|---|
| Monorepo | Nx + pnpm workspaces; module-boundary tags; per-project `project.json` targets |
| Frontend | Next.js 15 (App Router / React Server Components), TypeScript, Tailwind CSS, Framer Motion (LazyMotion strict) |
| Cinematic | Raw three.js 0.171 + GSAP + Lenis (no React-Three-Fiber), demand render loop, EffectComposer post |

### 0.4 Backend architecture — Clean Architecture per service
Each microservice is layered so business rules never depend on frameworks:
- **domain/** — pure entities, value objects, business rules. No Nest, no Prisma.
- **application/** — use-cases + ports (interfaces the domain needs: repositories, clocks, event buses).
- **infrastructure/** — adapters that implement the ports: Prisma repositories, Redis, mappers, external clients.
- **presentation/** — NestJS controllers + DTOs (validation) that call use-cases and return `Result<T>`.

`Result<T>` is a discriminated success/failure envelope (from `@fardeen/shared`/`@fardeen/types`) so
use-cases return typed outcomes instead of throwing; a global exception filter/interceptor maps them to
HTTP. Cross-service contracts live in `@fardeen/types` so the frontend and every service share one source
of truth. Sync service-to-service calls use NestJS TCP (`@MessagePattern`); async domain events go over
Redis (stream + pub/sub). Data is database-per-service (one Postgres instance, multiple logical DBs).

### 0.5 Request/data flow

### 0.7 Conventions & cross-cutting notes
- **Compiled-dist fleet:** on the low-memory dev machine the ts-node fleet is too heavy, so services are
  compiled to CommonJS with `main → dist/index.js`; `scripts/run-svc.cjs` bootstraps env (root + app
  `.env.local`), chdir's, and `require`s `dist/main.js`. (ts-jest / Nx / Next still use tsconfig paths → `src`.)
- **Native dev stack:** `dev-up.ps1` starts Postgres+Redis (via `fardeen-dev-infra\start-infra.ps1`),
  gates on `pg_isready`, then launches the 10 services + frontend inside a Windows **Job Object**
  (`KILL_ON_JOB_CLOSE`) so everything dies when the terminal/VS Code closes. `-Prod` serves a lean
  `next start`. `dev-down.ps1` tears down.
- **Reduced-motion / accessibility:** every animation layer (cinematic, scrubber, custom cursor, hero
  tools) is gated on `prefers-reduced-motion` and, where relevant, pointer type + WebGL support, with
  clean static fallbacks; SSR is never broken.
- **The homepage cinematic** currently mounts the raw-three.js `CinematicMount` (Scenes 1–11). A hybrid
  scroll-scrubbed frame-sequence walkthrough (`WalkthroughScrubber`) exists as an alternative path; its
  homepage wiring was built and later reverted per the owner — see Section 2.

### 1.2 Middleware — admin route gate (ADR-005)

`src/middleware.ts` gates `/admin/*` (`matcher:['/admin/:path*']`). **Presence check only** — the authoritative role check runs server-side in the `(panel)` layout; all mutations are RBAC-enforced by the gateway. Reads Next-owned cookies `fardeen_admin_at`/`fardeen_admin_rt`; `hasSession` = either has a value.
- On `/admin/login`: if `hasSession` → redirect to `/admin`; else allow.
- Otherwise: if no session → redirect to `/admin/login` with `?next=<pathname>` (unless the path is exactly `/admin`). Else `NextResponse.next()`.

### 1.8 ADR-005 — admin session (server-only libs)

The admin session lives entirely in httpOnly cookies set by our own Next route handlers; the access token is never exposed to client JS. The browser calls only same-origin `/api/admin/*`, which attach the Bearer token server-side and refresh transparently — no CORS, no tokens in JS.

- **`lib/admin/session.ts`** — cookies `AT_COOKIE='fardeen_admin_at'`, `RT_COOKIE='fardeen_admin_rt'` (distinct from the gateway's own `fardeen_rt` at `Path=/api/v1/auth`). `ADMIN_ROLES=['admin','editor']`. `AdminClaims={sub,email,role,exp}`. `b64urlDecode` handles Node `Buffer` and edge `atob`. **`decodeClaims(token)` decodes the JWT payload WITHOUT verifying its signature** — the token was minted by the gateway during a verified login and stored httpOnly by our server, and every real data call is re-verified + RBAC-checked by the gateway, so decoding here only drives routing/role-gating (defence-in-depth), never authorization. `isExpired(claims,skew=30s)`, `isAdminRole(role)`.
- **`lib/admin/cookies.ts`** — `setSessionCookies`/`clearSessionCookies` on a `NextResponse`. `SESSION_MAX_AGE=14 days` (= gateway refresh TTL). baseOptions: `httpOnly`, `sameSite:'lax'`, `secure` only in prod, `path:'/'`. The AT cookie deliberately outlives the JWT's short API TTL so the server can still decode its role claim; the proxy checks `exp` and silently refreshes.
- **`lib/admin/gateway.ts`** — server-only gateway client for the route handlers. `GATEWAY_RT_NAME='fardeen_rt'`. `extractRefreshToken(res)` pulls `fardeen_rt` out of `Set-Cookie` (undici `getSetCookie()` when available) to re-home it as our own httpOnly cookie. `gatewayLogin`/`gatewayRefresh`/`gatewayLogout`/`callAdmin(method,adminPath,accessToken,{body?,search?})` (pure passthrough to `/admin/*` with `Authorization: Bearer`; **no refresh here** — the proxy owns 401→refresh→retry). `cache:'no-store'` throughout.

### 1.9 ADR-005 — admin API route handlers (`app/api/admin/**`)

All `runtime='nodejs'`, `dynamic='force-dynamic'`.
- **`session/login/route.ts`** (`POST`) — validates with shared `loginSchema` → `VALIDATION_ERROR`; `gatewayLogin`; **rejects a successfully-authenticated non-admin (`visitor`) with 403 FORBIDDEN** (no session); on success sets httpOnly cookies, returns only `{data:{user:{email,role}}}` (access token never returned).
- **`session/logout/route.ts`** (`POST`) — best-effort `gatewayLogout`, `clearSessionCookies`, `{data:{ok:true}}`.
- **`[...path]/route.ts` — the same-origin BFF proxy** (GET/POST/PATCH/DELETE → `handle`). `safeAdminPath(segments)` rejects empty/`.`/`..`/slash/backslash (traversal defence), `encodeURIComponent`s, joins — `null`→404 so the target is always under `/admin/`. Reads cookies; both absent → `unauthorized()` (401 + clears cookies). **Proactive refresh**: if AT missing/undecodable/expired and RT exists → `gatewayRefresh`. Calls `callAdmin`; **reactive refresh**: on 401 (once) refresh + retry. Returns gateway JSON verbatim; if tokens rotated, persists via `setSessionCookies`.

## 2. Frontend — Cinematic Engine, Scroll Scrubber, Custom Cursor, Hero Tools, Hooks

The cinematic/interactive/hooks layer: a **raw three.js scroll-scrubbed 3D "construction journey"** (no React-Three-Fiber — React stays entirely out of the render path), a **frame-sequence hybrid walkthrough scrubber**, two **Framer-Motion micro-interactions** (custom cursor + hero tool cluster), and the **capability-detection hooks** that gate all of it. Everything is SSR-safe, reduced-motion-aware, and no-WebGL-safe by construction.

```
CinematicMount (gate)                     -- hooks: useReducedMotion, useWebGLSupport
  \- dynamic(ssr:false) CinematicExperience
        |- createWorld()   (world.ts)     -- procedural three.js scene + camera + handles
        |- enrichWorld()   (world.ts)     -- async HDRI IBL + PBR + GLB furniture/props
        |- createPipeline()(pipeline.ts)  -- EffectComposer (SSAO->Bloom->ACES->Vignette) + adaptive tiers
        |- createDirector()(director.ts)  -- ONE scrubbed GSAP timeline over SCENES (scenes.ts)
        |- Lenis                          -- sole scroll authority -> single gsap.ticker -> ScrollTrigger
        \- demand render loop             -- one frame per scrub tick; window.__fardeenSeek/__fardeenPerf seams

WalkthroughScrubber (standalone, not wired) -- canvas frame-sequence player (hybrid path)
ParticleField / HeroTools                   -- canvas background + Framer micro-interactions
```

**Wiring (verified):** `CinematicMount` is rendered in `app/(marketing)/page.tsx`. `ParticleField` is mounted once as the first body child in the root layout. `HeroTools` is rendered in `components/sections/hero.tsx`. `WalkthroughScrubber` is **not** imported anywhere except its own file (standalone, review-pending).

### `components/cinematic/cinematic-mount.tsx`
The gate + lazy activator. Computes `enabled = !reducedMotion && webgl === true`; if not enabled renders `null` (static DOM stands in). `CinematicExperience` imported via `next/dynamic` `ssr:false`, `loading:()=>null` (three/gsap/lenis bundle never touches SSR). An effect attaches one-shot passive listeners for `['wheel','pointermove','touchstart','keydown']`; the first flips `active`. **`scroll` is deliberately excluded** — automated audits (Lighthouse) only programmatically scroll, so the WebGL bundle never loads during measurement (no LCP/TBT hit). Until active, paints a layout-reserving placeholder `height:${SCENE_COUNT * 80}vh` with a sticky inner div (zero CLS on activation); `aria-hidden`.

### `components/cinematic/cinematic-experience.tsx`
The pinned canvas host + engine orchestrator (raw three.js). Decorative (`aria-hidden`) — every word of copy also lives in the static DOM below.
1. **Renderer** — `WebGLRenderer({antialias, powerPreference:'high-performance', alpha:false})`, DPR capped at 2, `ACESFilmicToneMapping` exposure 1.0, shadows `PCFSoftShadowMap`.
2. **Demand render loop** — renderer idle when not scrolling: `render()` calls `world.updateAmbient(elapsed)`, `camera.lookAt`, `pipeline.render()`; every 500ms samples FPS → `pipeline.adapt(fps)` + updates `window.__fardeenPerf={dpr,drawCalls,triangles,tier,fps}`. `invalidate()` coalesces via a `renderReq` guard → at most one `requestAnimationFrame(render)` per scroll tick.
3. **Pipeline + async enrichment** — `pipeline=createPipeline(renderer,scene,camera,invalidate)`, then `void enrichWorld(world,renderer,invalidate)` (fire-and-forget; never blocks LCP).
4. **Lenis as sole scroll authority** — one `Lenis` (`duration:1.1`, exp easing, smoothWheel, touchMultiplier 1.5); `lenis.on('scroll', ScrollTrigger.update)`; **Lenis's RAF is the single `gsap.ticker`** (`gsap.ticker.add(t=>lenis.raf(t*1000))`, `lagSmoothing(0)`). Exactly one animation clock; three.js renders on demand.
5. **Director** — `createDirector({camera,handles,lookTarget,spacer,copyEls,invalidate})`; **`window.__fardeenSeek = director.seek`** exposed as a verification seam (drive timeline to `0..1`).
6. **Teardown** deletes `__fardeenSeek`, `director.dispose()`, `pipeline.dispose()`, removes ticker fn, `lenis.destroy()`, kills all ScrollTriggers, `world.dispose()`, `renderer.dispose()`.
- **Markup:** tall spacer (`${SCENE_COUNT*80}vh`, `data-cinematic-spacer`, aria-hidden) with a sticky full-screen stage + absolute `<canvas>`, a pointer-events-none copy overlay mapping `SCENES` to hidden captioned blocks (gold eyebrow + display title), + top/bottom gradient scrims.

### `components/cinematic/walkthrough-scrubber.tsx`
The **hybrid cinematic path** — scroll-scrubbed pre-rendered frame-sequence player. An offline render (Blender Cycles / UE5 / purchased clip) is exported to numbered JPEG/WebP frames; this pins a canvas and draws the frame matching scroll progress. Uses **~zero GPU 3D budget** (one `drawImage` per changed frame). **NOT yet wired into the homepage** (standalone, review-pending). Props: `frameCount` (req), `basePath`, `pad=3`, `ext='jpg'`, `perFrameVh=60`, `captions?`. Why frames not `<video>`: scrubbing H.264 `currentTime` snaps to sparse keyframes (janky); a drawn frame sequence scrubs perfectly both directions (Apple product-page technique), verified ~51fps. Preload effect builds `count` Images (`reducedMotion?1:frameCount`), `onload=onerror` increments `done`/`progress`, flips `ready`. Draw effect (skipped under reduced motion): `fit()` sizes backing store to `dpr≤2`; `drawIndex` cover-fit blit; RAF loop computes `p=clamp(-rect.top/(offsetHeight-innerHeight),0,1)` → `idx` and **only redraws on index change**. Reduced-motion → single static `<img>` of frame 0. Markup: tall track (`frameCount*perFrameVh vh`), sticky black stage, canvas, optional serif caption, branded gold loader bar. Companion assets: six placeholder frame folders (exterior 40, suite/kitchen/dining/bedroom/bathroom 30 each) + a standalone `index.html` mechanism-proof demo (`window.__scrubReady`/`__scrubGoto` seams + FPS HUD).

### `lib/cinematic/world.ts`
Builds the entire procedural world in raw three.js. Exports `createWorld():World`, `enrichWorld(world,renderer,invalidate)`, and `World`/`WorldHandles`. **`WorldHandles`** (tween surface): `env{skyMat,fog,sun,ambient}`, `villa{slab,rebar,walls[],columns[],upper,roof,shellMats[],claddingMat,glassMat,windowMat,interior,interiorLight,windowMesh,floorMat,furnitureGroup}`, `grass{group,material}`, `birds{group,flock,material}`, `gate{group,left,right}`, `terrainMat`.

### `lib/cinematic/pipeline.ts`
Photoreal post + adaptive-quality controller. `createPipeline(renderer,scene,camera,invalidate):Pipeline` (`render`,`setSize`,`adapt`,`tier`,`dispose`). Built on a `HalfFloatType` target (`samples:2` cheap MSAA). ## 3. auth-service + gateway

**auth-service** owns the Identity bounded context (its own `auth_db`, Clean Architecture, TCP message handlers only). **gateway** is the single public HTTP door: verifies RS256 access tokens locally, enforces RBAC, rate-limits, adds correlation ids, proxies to each service over a `ClientProxy`, resolves media, wraps everything in `Result<T>`/envelope. (`generated/**` Prisma clients + `dist/**` are build artifacts, omitted.)

### 3.1 auth-service

**`prisma/schema.prisma`** (`auth_db`, client → `../generated/client`):
- **`User`** → `users`: `id` uuid PK; `email` unique; `passwordHash`→`password_hash`; `role` default `"visitor"`; `status` default `"active"`; `createdAt`/`updatedAt`.
- **`RefreshSession`** → `refresh_sessions`: `id`; `userId`; `tokenHash` unique; `familyId`; `userAgent?`; `expiresAt`; `revokedAt?`; `createdAt`. Indexes on `userId`, `familyId`. Note: this is the durable schema-of-record; the **active/revocable rotation store is Redis** (the running code uses only Redis for refresh sessions; table is audit for a later phase).
- Migration creates both tables + unique/plain indexes. `seed.ts` idempotently upserts an admin (`SEED_ADMIN_EMAIL` default `admin@fardeen.local`, `SEED_ADMIN_PASSWORD` default `Admin@12345`, role `admin`, bcrypt 10).

**`main.ts`** — hybrid bootstrap: connect TCP microservice (`Transport.TCP`, host `SERVICE_BIND_HOST??0.0.0.0`, port `TCP_PORT??4001`) + HTTP `listen(HTTP_PORT??3001)` for `/health`+`/ready` only.

**Domain:**
- `User` aggregate — `register({id,email,passwordHash,role?,createdAt})` (default role `visitor`, status `active`) / `rehydrate`. `isActive()`, `verifyPassword(plain,compare)` (false if inactive, else delegates to a comparator — hashing libs stay out of domain), `changeRole(role)` (throws `ForbiddenError` if inactive), `deactivate()`.
- `RefreshSession` — `isActive(now)` (not revoked && not expired), `revoke(now)` (idempotent). Only the token *hash* is modeled.
- `Email` VO — trim+lowercase + regex, `ValidationError` on failure.
- `auth-events.ts` — `AUTH_EVENTS = { userRegistered:'user.registered', userRoleChanged:'user.roleChanged' }`.
- `UserRepository` port (`USER_REPOSITORY` symbol): `findById`, `findByEmail`, `existsByEmail`, `save`.

**Application ports** (each = Symbol + interface): `PASSWORD_HASHER` (`hash`/`compare`); `TOKEN_SIGNER` (`sign({id,email,role})→AccessToken`, short-TTL RS256); `REFRESH_SESSION_STORE` (`issue`/`get`/`markRotated`/`revokeFamily`); `EVENT_PUBLISHER`. `toErr(e)` maps `DomainError`→`err`, rethrows else. `toUserProfile(user)` mapper.

**Use-cases:**
- `RegisterUser` — `Email.create` → `existsByEmail`→`EMAIL_TAKEN` → hash → `User.register` → save → publish `user.registered` → `ok(profile)`.
- `LoginUser` — single generic `INVALID_CREDENTIALS` for unknown email OR wrong password OR inactive; on success sign access + issue refresh → `ok({access,refreshToken,profile})`.
- `RefreshToken` — rotation + reuse detection: `get(token)` null→`REFRESH_INVALID`; `!active`→**`revokeFamily`+`REFRESH_REUSE`** (replay of a rotated token nukes the family); expired→`REFRESH_INVALID`; else `markRotated`, reload user (missing/inactive→`revokeFamily`+`UNAUTHORIZED`), `issue` in same family, sign new access.
- `Logout` — `get(token)`; if found `revokeFamily`; always `ok` (idempotent).
- `GetMe` — `findById`→`USER_NOT_FOUND` or `ok(profile)`.

**Infrastructure:** `env.ts` (`AUTH_CONFIG` + Zod; vars: `AUTH_DATABASE_URL` req, `REDIS_*`, `JWT_PRIVATE_KEY|_PATH`, `JWT_ACCESS_TTL=900`, `JWT_ISSUER=fardeen-auth`/`JWT_AUDIENCE=fardeen-api`, `REFRESH_TTL_SECONDS=1209600`, `BCRYPT_ROUNDS=10`, `TCP_PORT=4010`, `HTTP_PORT=3010`). `PrismaUserRepository` (`save` upsert — create full row, update only role/status/passwordHash). `RedisRefreshSessionStore(redis,ttl)` — stores only SHA-256 of the opaque token; keys `auth:rt:tok:<sha>` + family set `auth:rt:fam:<familyId>`; `issue` (randomBytes 32 hex, SET EX ttl+60, SADD famKey), `markRotated` (flip active:false), `revokeFamily` (SMEMBERS→DEL). `RedisEventPublisher` dual-write (`XADD stream:<name>` + `PUBLISH <name>`). `BcryptPasswordHasher`, `Rs256TokenSigner` (`jwt.sign({email,role,type:'access'}, RS256, subject:id, expiresIn, issuer, audience)`). `AuthMessageController` (TCP only).

**auth-service TCP handlers:** `auth.register`→RegisterUser, `auth.login`→LoginUser, `auth.refresh`→RefreshToken, `auth.logout`→Logout, `auth.me`→GetMe. (`auth.validate` is defined in contracts but NOT implemented — the gateway verifies tokens locally, ADR-004.)

### 3.2 gateway

Only public HTTP surface, global prefix `api/v1`. App-wide: helmet, cookie-parser, CORS(credentials), `ValidationPipe({whitelist,transform})`, correlation-id middleware, global ThrottlerGuard, global `AllExceptionsFilter`, global `ResponseEnvelopeInterceptor`.

**Config (`GATEWAY_CONFIG`):** `GATEWAY_PORT=4000`, `GATEWAY_GLOBAL_PREFIX=api/v1`, `CORS_ALLOWED_ORIGINS`, `JWT_PUBLIC_KEY|_PATH` (RS256 verify), `JWT_ISSUER/AUDIENCE`, per-service `<SVC>_SERVICE_HOST/PORT` (auth 4010 … admin 4017), `REFRESH_COOKIE_NAME=fardeen_rt`, `REFRESH_TTL_SECONDS`, `RATE_LIMIT_TTL=60`/`RATE_LIMIT_MAX=100`, `AUTH_RATE_LIMIT_MAX=10`, `WRITE_RATE_LIMIT_MAX=5`.

**Common:** `FardeenRequest` (correlationId/requestId/user/cookies); `CorrelationIdMiddleware`; `DomainHttpError` (carries an `AppError`); `http-status.map.ts` (`statusForCode`: VALIDATION_ERROR→400, INVALID_CREDENTIALS/UNAUTHORIZED/REFRESH_*→401, FORBIDDEN→403, EMAIL_TAKEN/CONFLICT→409, *_NOT_FOUND→404, default 400); `AllExceptionsFilter` (`@Catch()`, maps DomainHttpError/HttpException/unknown→`{error:{code,message,details}, meta:{requestId}}`, **never leaks stacks**); `ResponseEnvelopeInterceptor` (`{data,meta:{requestId}}`, passes through pre-shaped `{data,meta}`); `ZodBody<T>(schema)`; `callService(client,pattern,payload)` (`firstValueFrom(send)`, `!ok`→throw `DomainHttpError`); `ClientsWarmup` (eager connect all 8 proxies); **`MediaResolver`** (`resolveMany(ids)` dedupes, degrades to `{}` if media down; media resolved ONLY at the gateway).

**Auth (gateway-side):** `JwtAuthGuard` (requires `Authorization: Bearer`, verifies **locally** with `jwtPublicKey` RS256+issuer+audience — no round-trip, ADR-004; attaches `req.user`); `RolesGuard` (`@Roles` metadata via Reflector; no metadata→allow, no user→401, role not in set→403); `Roles(...roles)` decorator (`admin`|`editor`|`visitor`).

**Full gateway endpoint table (under `/api/v1`):**

| Method | Path | Purpose | Auth / rate |
|---|---|---|---|

## 7. notification-service + admin-service + packages (types, ui, shared, utils, config)

### 7.1 notification-service (TCP 4018 / HTTP 3018)
Event-driven, **no `@MessagePattern`** — its "endpoints" are Redis-Stream subscriptions. Owns `notification_db`; reacts to domain events over **Redis Streams + a consumer group** (durable, retry-safe); sends email (Nodemailer/SMTP → Maildev in dev); records a delivery log + a durable idempotency ledger.

**`prisma/schema.prisma`** (client → local `../generated/client`):
- **`Notification`** → `notifications`: `channel` (email|webhook); `template`; `to`→`to_addr`; `payload Json`; `status` default "queued" (queued|sent|failed); `attempts` default 0; `correlationId`; `createdAt`. `@@index([correlationId])`,`([status])`.
- **`ProcessedEvent`** → `processed_events`: `correlationId` PK; `processedAt`. Durable idempotency ledger — a correlationId is recorded once fully handled, so redelivery is a safe no-op.

**Domain:** `Notification` aggregate — `create` (queued, attempts 0) / `rehydrate` (copies props); mutators `incrementAttempt()`, `markSent()`, `markFailed()`. Port `NOTIFICATION_REPOSITORY` (`save`, `countByStatus`, `isProcessed(correlationId)`, `markProcessed(correlationId)`).

**Application:** `EMAIL_SENDER` port (`send({to,subject,text,html?})`). `deliverEmail(email,repo,{template,correlationId,payload,message})` — creates Notification, `incrementAttempt()`, `email.send`; success → `markSent()`+save; failure → `markFailed()`+save+**rethrow** (so the stream consumer does NOT ack → retried). Event handlers (each guards `isProcessed(correlationId)` then `markProcessed`):

| Handler | Event | Emails | Templates |
|---|---|---|---|
| `HandleContactSubmitted` | `contact.submitted` | 2 — sales inbox (`New contact enquiry: <subject>`) + auto-reply (`We received your message — Fardeen`) | contact-sales, contact-autoreply |
| `HandleQuotationRequested` | `quotation.requested` | 1 — sales inbox (`New quotation request <id>`) | quotation-sales |
| `HandleQuotationStatusChanged` | `quotation.statusChanged` | 1 — client (`Your Fardeen quotation <id> is now "<to>"`) | quotation-status |

**Infrastructure:** `env.ts` (`NOTIFICATION_DATABASE_URL` req, `REDIS_*`, `SMTP_HOST`=localhost/`SMTP_PORT`=1025, `MAIL_FROM`, `SALES_INBOX`, `NOTIFICATION_GROUP`=notification/`NOTIFICATION_CONSUMER`=notification-1, `NOTIFICATION_MAX_ATTEMPTS`=5, `NOTIFICATION_RECLAIM_IDLE_MS`=15000, `NOTIFICATION_BLOCK_MS`=5000, `NOTIFICATION_BATCH`=10). `PrismaNotificationRepository` (`markProcessed` upsert). `NodemailerEmailSender` (SMTP transport, secure:false, auth only if user set). **`StreamConsumer`** (heart of ADR-002 durable delivery) — two ioredis connections; `onApplicationBootstrap` `XGROUP CREATE … 0 MKSTREAM` per stream (swallows BUSYGROUP) then `readLoop`+`reclaimLoop`. `readLoop`: `XREADGROUP … BLOCK … STREAMS … '>'` → handle each. `handle`: parses `event` JSON; **acks+drops poison/unknown** messages; handler success → `XACK`; handler throw → no ack (reclaimed). `reclaimLoop`: every `reclaimIdleMs` `XPENDING … IDLE`; `deliveries > maxAttempts` → **dead-letter** (XACK+warn); else `XCLAIM`+reprocess. A message XADD'd while the consumer is DOWN is still delivered on restart (pub/sub would lose it). `notification.module.ts` eagerly instantiates `StreamConsumer` mapping the 3 events → handler `execute`.

**Consumed events:** `stream:contact.submitted`→HandleContactSubmitted; `stream:quotation.requested`→HandleQuotationRequested; `stream:quotation.statusChanged`→HandleQuotationStatusChanged (idempotency via ProcessedEvent; retry via XPENDING/XCLAIM; drop after maxAttempts=5). Integration spec `event-durability` proves — against real Redis Streams + Postgres — delivery, **DURABILITY** (drain backlog published while consumer down), **IDEMPOTENCY** (same correlationId twice → 1 email/row), **RETRY→DEAD-LETTER**.

### 8.5 Run / deploy overview

**Light dev (Windows, no Docker) — the primary path here.** Docker/WSL2 is unrecoverable on this machine, so infra runs natively: Postgres 5432 + Redis 6379 started by `C:\Users\EARNINGFISH\fardeen-dev-infra\start-infra.ps1`, and services run as **compiled dist** (`node dist/main.js`, ~70 MB each) rather than the ts-node fleet. MinIO :9000 is not staged, so media-service stays down (rest of stack is fine).

`dev-up.ps1` (persistent, run in a VS Code terminal, `-Prod` and `-Rebuild` switches):
1. **Infra gate** — if 5432/6379 aren't listening, launches `start-infra.ps1`; then waits on `pg_isready.exe` (up to 30 s) so services don't race Postgres and crash with P1001 (an open port ≠ accepting queries). Warns if MinIO 9000 is down.
2. **Build-if-stale** — builds `types,shared,utils` + the 10 services to dist via `nx run-many -t build --parallel=1` when `packages/types/dist/index.js` or any `apps/<svc>/dist/main.js` is missing (or `-Rebuild`). `-Prod` also `next build`s the frontend if `.next/BUILD_ID` is absent.
3. **Free stale ports** — kills listeners on all 20 stack ports (orphans from a hard-closed terminal).
4. **Start** — the 10 services in dependency order (leaf/owning → BFF → gateway: project, service-management, cms, contact, quotation, media, notification, auth, admin, gateway), each launched via `node scripts/run-svc.cjs apps/<svc>` staggered 1.5 s; then the frontend (`next dev -p 3000`, or `next start -p 3000` under `-Prod`, ~200 MB vs ~1.2 GB). PIDs written to `.dev-pids`, logs to `.dev-logs/*.{out,err}.log`.

All children are placed in a **Windows Job Object created with `CreateKillOnClose` (`JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE`, LimitFlags `0x2000`)** via inline P/Invoke (`Win32Job` C# type), so Ctrl+C or closing the terminal terminates every service cleanly — no orphans. A health gate (180 s deadline; ready when gateway `/api/v1/health` + frontend `/` respond) precedes a foreground status loop printing `services N/10 | frontend ok`. `finally { Stop-Stack }` force-kills tracked children on exit.

`dev-down.ps1` — cleanup for a hard-killed terminal: kills tracked `.dev-pids` PIDs and frees all 20 stack ports; leaves shared Postgres/Redis running.

`scripts/run-svc.cjs` — env bootstrap for compiled services: compiled `node dist/main.js` doesn't get Nx's auto `.env.local` loading, so this replicates it — loads root `.env.local` then `apps/<svc>/.env.local`, sets `NODE_ENV`, `chdir`s into the app dir (so `../../secrets` + prisma resolve), then `require`s `dist/main.js`.

**Full Docker dev (`docker compose up`, parity/CI path).** `name: fardeen`. All 11 Node apps share one image (`infra/docker/node.Dockerfile` `dev` target) via YAML anchors: repo bind-mounted at `/workspace`, `node_modules` in a named volume so the host mount can't clobber container deps, `.nx` + `.next` shadowed as anonymous volumes; each runs `pnpm nx dev <app>` (Nest `--watch` / Next dev). Health checks + `depends_on: service_healthy` sequence boot: postgres (`pg_isready`), redis (`redis-cli ping`), minio (`/minio/health/ready`) + a one-shot `createbuckets` (`minio/mc`, creates bucket + anonymous download policy) → the 9 services (each Nest health `GET :3001/health`) → gateway (`:4000/api/v1/health`, depends on all 9 + redis) → frontend (`:3000/api/health`, depends on gateway). Postgres init mounts `infra/postgres/init/01-create-databases.sql` (creates the 8 per-service DBs; admin-service intentionally has none). `docker-compose.infra.yml` runs only Postgres/Redis/MinIO (+ MailDev on 1025/1080) with **host ports shifted** (5435/6381/9002/9003) for machines where the defaults are taken; shares `name: fardeen` so data/network match the full stack.

**Production (`docker-compose.prod.yml`, `name: fardeen-prod`).** Per-app minimal non-root multi-stage images (node.Dockerfile `prod` target = `pnpm deploy --prod --legacy` → `node dist/main.js` as unprivileged `app` user, tini as PID 1; frontend via `frontend.Dockerfile` using Next `output:'standalone'`). No bind mounts / no node_modules volume; `restart: unless-stopped`; resource limits (0.75 cpu / 512 MB, 128 MB reservation); service ports internal-only — **only gateway :4000 and frontend :3000 published**. Postgres built from `infra/postgres/Dockerfile` (init baked in, no bind mount). Migrations run as a **one-shot job** (`--profile migrate`, node.Dockerfile `tools` target running `infra/scripts/migrate.sh` — `prisma migrate deploy` per service:DB pair, skipping schemaless services; admin-service excluded), **never on service boot**.

`.dockerignore` keeps host artifacts (node_modules with wrong-platform binaries, dist, .next, .nx, coverage, .env*, logs, md except README) out of the build context. `infra/redis/redis.conf` and `infra/minio/create-buckets.sh` are canonical reference copies of logic that is inlined as CLI flags / compose init containers so prod needs no bind mounts.
